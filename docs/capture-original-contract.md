# 원본 이미지 및 크롭 전송 계약 — 2026-11-07

이 문서는 프런트에서 구현한 v0 확장 제안이다. 실제 백엔드 적용은 별도이며, 기존 서버 호환이 검증된 상태가 아니다.

POST /api/v1/jobs, multipart/form-data:
- photo: 전체 화각 JPEG. 원본 해상도를 유지하며 EXIF 회전/반사만 픽셀에 적용한다. 크롭/축소하지 않는다. JPEG 재인코딩이 있으므로 파일 바이트 원본 보존을 뜻하지 않는다.
- w, h: 전송 이미지의 실제 가로/세로 정수 픽셀.
- rotation: 0 (방향 정규화 완료). fx는 알 수 있을 때만 전송.
- crop: JSON 문자열 {"x":50,"y":0,"width":300,"height":300}.

좌표는 방향 정규화된 photo의 좌상단 원점, 정수 픽셀이다. 영역은 [x,x+width), [y,y+height)이며 폭/높이는 양수, 범위는 이미지 안이어야 한다. 카메라의 선택 비율은 중앙 크롭으로 계산하고, 앨범 입력은 기본적으로 전체 영역이다.

기존 capture JSON 필드 대신 v0 명세대로 w/h/rotation/fx 개별 필드를 보낸다. crop 필드가 무시되는 구서버로 자동 우회하지 않는다. 서버 구현 시 요청 검증 및 capture.crop 응답 보존을 추가해야 한다. 프런트의 기존 응답 파서는 crop 없는 과거 job도 읽을 수 있다.

서버 처리 순서: 전체 photo로 depth/장면 분석 → 동일 원본 좌표계에서 크롭 영역을 고려하여 합성 → crop 영역의 최종 이미지 출력. retry는 동일한 원본/좌표를 사용한다. 원본 삭제와 보관 정책은 기존 v0를 유지한다.

프런트는 CaptureDraft에 전체 이미지·표시용 크롭·CaptureInfo를 분리해 보관한다. 확인/처리 화면은 표시용 크롭 전체를 contain으로 보여준다. 모의 저장소는 전달받은 원본에 동일 좌표를 적용해 결과를 만든다. 센서의 스틸 촬영과 플랫폼 프리뷰 화각 차이는 실제 장치 검증 대상이며 프런트의 비율 선택으로 원본을 사전에 잘라서는 안 된다.
